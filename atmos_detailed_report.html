Section 2

Deep dive: what works

Problem-market fit is exceptional

Score driver: +8 pts

The voluntary carbon market is worth ~$2B today and is projected to reach $50B+ by 2030. The central problem — that carbon credits can't be trusted because MRV is done manually — is real and costing institutional buyers billions in greenwashing risk.

Atmos targets infrastructure, not a marketplace. That's the smarter angle. Every carbon project needs MRV; Atmos becomes a settlement layer, not a competitor to existing platforms.

9 entity types (biochar, agroforestry, solar, EV, aviation, shipping...) with proper methodology coverage (IPCC, VCS, VM0047, CORSIA) signals domain expertise that most hackathon teams can't fake.

Tech stack ambition is top-tier

Score driver: +8 pts

Sentinel-2 satellite data — real ESA imagery source for NDVI vegetation index, land-use classification, and NASA FIRMS fire detection. Not mocked.

Anthropic Claude AI engine — entity-specific prompts for 8-dimensional fraud detection and CO₂e estimation using IPCC/VCS methodologies. Confidence scoring is multi-factor (0–100 pts across 4 axes).

Groth16 ZK proofs — privacy-preserving verification anchored on-chain. This is a genuine differentiator; most carbon projects expose sensitive land-boundary data publicly.

Dodo Payments + Svix webhooks — INR/UPI → USDC → Solana settlement pipeline built, HMAC-SHA256 webhook verification implemented correctly.

Codebase is production-minded

Score driver: +6.5 pts

Monorepo with pnpm workspaces, TypeScript end-to-end, esbuild for production bundling — not a toy project structure.

Vitest + Supertest test coverage for the API server, Docker + docker-compose for infra, CI/CD via GitHub Actions workflows in place.

OpenAPI spec with Orval codegen — shows API contract thinking. Pino structured logging.

48 commits across 3 contributors is reasonable but low; some senior judges will check commit history to verify build depth.

Section 3

Deep dive: critical gaps

Solana integration is incomplete — disqualifying risk

Score killer: −6.5 pts

The README status table explicitly lists "Full Solana minting integration" as ⏳ planned. The hackathon requirement is Solana integration. Judges will check the repo and find no working SPL token minting.

Architecture diagram shows Solana Devnet as a target but the code path from settlement → SPL mint is unimplemented. The `lib/integrations` folder likely has stubs, not working code.

Without on-chain minting, Atmos is a carbon verification API — a solid API, but not a Solana project. This alone can move a project from shortlisted to eliminated.

Zero user traction — the biggest Colosseum weakness

Score killer: −7.5 pts

0 GitHub stars, 0 forks. No demo users. No Twitter/Telegram community evidence. No testimonials. Colosseum's own workshop explicitly states judges look for early traction proof — Twitter feedback, Telegram conversations with potential users, usage data.

This is a solvable problem before submission. Even 3–5 carbon project operators testing the MRV pipeline and giving a quote is enough to demonstrate product-market validation.

India has a thriving carbon project ecosystem (biochar, solar, agroforestry). The team should be able to find pilot users quickly given their location in Gujarat.

Infrastructure fragility undermines the "settlement layer" pitch

Score drag: −4 pts

Settlement records use an in-memory store — explicitly noted in the repo as `settlement-store.ts`. Data is lost on server restart. For a product pitching itself as "immutable financial infrastructure," this is a credibility gap.

PostgreSQL + PostGIS is in the architecture diagram and `lib/db` folder exists, but migrations are not wired into the running app. The gap between architecture diagram and actual implementation will be spotted.

The `vercel-deploy.log` committed to root is a minor unprofessional signal — judges notice repo hygiene.

Pitch video quality is unknown — and it's the #1 judging input

Score risk: unknown

Colosseum's co-founders have stated: "The pitch video is the most important element. It is usually the first item judges review and can determine whether a project is shortlisted for deeper evaluation."

A strong video needs: hook (the problem in 20 seconds), live product demo, market size claim, team credibility. A weak or absent video means judges may never see the technical depth underneath.

Section 6

Prize track recommendation

Primary: RWA / DePIN track

Best fit for carbon tokenisation infrastructure

Real-world asset tokenisation with verifiable provenance is exactly what this track rewards. Atmos's MRV → ZK proof → SPL token flow is a textbook RWA infrastructure play.

Fewer teams target climate infrastructure vs DeFi, so competition density is lower.

Secondary: Public Goods award ($10K)

Open MRV API benefits the whole ecosystem

If the MRV API is open-source and documented as a developer tool, it qualifies for the Public Goods track. This is a separate prize — a project can win both.

The OpenAPI spec (already in lib/api-spec/openapi.yaml) is the foundation. Add clear usage docs and an open developer portal.

Final verdict

Atmos has the strongest problem-market fit and most sophisticated technology of any climate project likely to enter a Colosseum hackathon. The idea is fundable. But as of today it is a compelling prototype with a missing core deliverable — working Solana integration. Fix that, get 3 real users, and make a great video, and this project has a genuine shot at the RWA track prize and high probability of accelerator consideration. Without those three things, it will be eliminated early despite its technical depth.
